# Известные проблемы и ограничения

Реестр ведётся с v0.1.0-design. Идентификатор `KI-XXX` присваивается один раз и
не переиспользуется. Закрытая проблема переносится в раздел «Решённые» со
ссылкой на версию.

## Открытые

### KI-003 — Из 360 задач собрано 180

**Статус:** контент-фаза; v0.3.0
**Влияние:** доступны 6 глав из 12 на каждом уровне; нельзя оценить полный
объём 360 задач и баланс всех глав.
**План:** v0.4.0 — 360 задач; v1.0.0 — публичный релиз. Каждая задача проходит
машинную и выборочную ручную проверку.

### KI-004 — Монетизация заблокирована требованиями RuStore

**Статус:** внешнее ограничение
**Влияние:** подписки и встроенные покупки в RuStore доступны ИП/юрлицам;
физлицо может публиковать бесплатное приложение.
**План:** v1.0.0 — бесплатный запуск без рекламы и IAP. Premium и rewarded
реклама — после оформления ИП/юрлица и обновления политики/декларации.

### KI-006 — URL политики конфиденциальности не опубликован

**Статус:** до релиза
**Влияние:** RuStore требует доступную страницу политики.
**План:** опубликовать `docs/legal/PRIVACY_POLICY.md` на
`iiruchating.ru/chess-problem/privacy` или GitHub Pages; указать URL в карточке
и в приложении.

### KI-007 — Название и package — рабочие

**Статус:** до первой публикации
**Влияние:** `Chess Problem`, `com.iilmchat.chessproblem` и store-название
«Chess Problem: шахматы» могут измениться.
**План:** проверить уникальность в RuStore, доступность домена/соцсетей и
юридическую чистоту до создания ключа подписи. После публикации package и
подпись не меняются.

### KI-009 — EN-контент собран для 180 задач, не для 360

**Статус:** контент-фаза; v0.3.0
**Влияние:** 180 production-задач имеют RU/EN; оставшиеся 180 задач требуют
редактуры и второй вычитки.
**План:** EN-поля обязательны в схеме; валидатор не пропускает пустые
`ru/en`. Финальная вычитка — перед v1.0.0.

### KI-017 — 180 задач нуждаются во втором человеческом ревью

**Статус:** v0.3.0
**Влияние:** факты линий проверены chess.js и `replay.mjs`, тексты собраны по
этим фактам; независимый редактор ещё не подтвердил стиль, отсутствие
спойлеров и качество объяснений.
**План:** ревьюер `tools/review/index.html` готов; пройти выборку 180 задач по
чек-листу CONTENT_AUTHORING, исправить тексты и только затем считать контент
готовым к v1.0.0.

### KI-018 — Demo-прогресс v0.2.0 пересекается с production ID

**Статус:** pre-release
**Влияние:** в v0.2.0 демо-задачи использовали `nov-001`, `pro-001`, `grm-001`;
в v0.2.1 эти ID принадлежат другим позициям. Локальный тестовый прогресс может
показать звёзды на новых задачах.
**План:** для тестеров очистить данные приложения; публичного релиза v0.2.0 не
было. Перед v1.0 добавить `contentVersion` в прогресс или namespace для demo.

### KI-010 — Планшетная раскладка не проверена

**Статус:** дизайн
**Влияние:** макет рассчитан на телефон 360–430 dp; на планшете доска может
выглядеть мелко.
**План:** max-width 560–640 dp, центрирование, увеличенные поля; проверка на
7–10" в v0.4.0.

### KI-011 — В прототипе нет сценария 0 звёзд

**Статус:** ограничение прототипа; в Android сценарий реализован
**Влияние:** прототип не показывает экран «Решение показано»; Android-версия
умеет раскрывать решение из результата провала.
**План:** синхронизировать прототип с Android в следующей итерации.

### KI-012 — Только тап-тап

**Статус:** ограничение прототипа и Android vertical slice
**Влияние:** не проверены перетаскивание фигуры, конфликт жестов со скроллом и
тактильная отдача при drag. TalkBack не навигирует по отдельным клеткам.
**План:** в Compose-доске реализовать drag-and-drop и семантику клеток;
прототип оставить тап-тап как основной сценарий.

### KI-013 — Упрощённая шахматная логика прототипа

**Статус:** прототип; Android использует chesslib 1.3.7
**Влияние:** прототип проигрывает одну захардкоженную линию и не проверяет
полные правила. Android проверяет FEN/SAN, легальные ходы, мат, превращение и
принимает альтернативный мат.
**План:** прототип оставить средством проверки композиции, не эталоном правил.

### KI-014 — Нет instrumented и screenshot-тестов

**Статус:** после v0.2.0
**Влияние:** CI проверяет unit-тесты `core`, сборку и lint, но не сценарии на
эмуляторе и не регрессии вёрстки.
**План:** Compose UI tests для решателя/подсказок/результата + screenshot tests
на 360×800 и 430×932.

### KI-015 — Долгий холодный старт на эмуляторе

**Статус:** наблюдение vertical slice
**Влияние:** на Pixel 6 API 36 первый запуск после установки занимает заметное
время; экран загрузки и светлая тема могут мелькать до чтения DataStore.
**План:** измерить на реальном устройстве; при необходимости вынести тему в
синхронный SharedPreferences-кэш и предзагружать контент в Application.

### KI-016 — Нет detekt и ktlint в сборке

**Статус:** план
**Влияние:** стиль Kotlin проверяется только компилятором и lint.
**План:** подключить detekt 1.23.8 + formatting, зафиксировать baseline и
добавить в CI.

## Решённые

### KI-008 — Пайплайн загрузки Lichess не автоматизирован

**Статус:** решено в v0.2.1
**Решение:** `tools/import-lichess.mjs` фильтрует CSV/ZST, собирает пул,
формирует drafts, принимает RU/EN sidecar, мержит паки и запускает валидатор;
`tools/lichess-selection.json` фиксирует 60 ID и порядок воспроизведения.

### KI-001 — Android-проект ещё не создан

**Статус:** решено в v0.2.0-vertical-slice
**Решение:** созданы `app`, `core`, `data`, `ui`, `build-logic`, Gradle wrapper
9.8.2, version catalog и convention-плагины. Debug APK собирается, запускается
на API 36 и проверен на эмуляторе.

### KI-005 — Нет Android CI и тестов на устройстве

**Статус:** решено в v0.2.0-vertical-slice
**Решение:** CI job запускает `:core:test`, `:app:assembleDebug`,
`:app:lintDebug`; ручная проверка выполнена на эмуляторе Pixel 6 API 36.
Instrumented/screenshot tests остаются в KI-014.

### KI-002 — Прототип использовал Unicode-фигуры

**Статус:** решено в v0.1.0-design
**Решение:** фигуры и иконки заменены на инлайновые SVG-спрайты
(`#p-pawn`…`#p-king`, `#i-*`); Unicode не используется. Ограничение по
шахматной логике вынесено в KI-013.
