# Руководство по ручному тестированию

**Статус:** первая редакция · **Дата:** 28.10.2026
**Связано:** [DESIGN](../design/DESIGN_V01_MVP.md) · [UI/UX SPEC](../design/UI_UX_SPEC.md) ·
[ARCHITECTURE](../development/ARCHITECTURE.md) · [RELEASES](../development/RELEASES.md) ·
[KNOWN ISSUES](../KNOWN_ISSUES.md)

Документ описывает, как проверять Chess Problem перед релизом. Android-код
собирается с v0.2.0; кейсы выполняются на устройстве/эмуляторе. Часть smoke-
сценариев уже пройдена на Pixel 6 API 36 (debug APK), полная матрица устройств
— перед публичным релизом.

> **Текущий статус v0.3.0:** пройдены холодный запуск, 180 production-задач,
> ход тап-тап, ответ соперника, мат в 2, подсказки, пауза, выход/continue,
> провал и продолжение, звёзды/XP, RU/EN, светлая/тёмная тема, Room-прогресс,
> настройки и «О приложении». Не пройдены: API 26, планшет, TalkBack,
> release-подпись, все 360 задач, IAP/реклама. Скриншоты —
> [docs/screenshots/android](../screenshots/android/README.md).

---

## 1. Цели и границы

### 1.1. Что проверяем

- установку, обновление и удаление;
- главную, уровни, главы и решатель;
- таймер, попытки, подсказки, продолжение;
- звёзды, XP, серию, достижения;
- разбор и навигацию;
- RU/EN, доступность, офлайн;
- производительность на нижней границе;
- контент: легальность, мат, локализация, дубли;
- store-артефакты и политику.

### 1.2. Что не проверяем в v1.0

- онлайн-игру, аккаунт, облако;
- покупки, рекламу, подписку (появятся в v1.1 после ИП/юрлица);
- iOS, планшетную двухпанельную раскладку (v0.4.0);
- шахматный движок/анализ партий (не входит в продукт).

## 2. Окружение и данные

### 2.1. Матрица устройств

| # | Устройство / эмулятор | Android | Зачем |
| --- | --- | --- | --- |
| D1 | Low-end телефон, 2 ГБ RAM, 720p | 8.0 (API 26) | Нижняя граница, производительность |
| D2 | Средний телефон | 10–12 | Основной сценарий |
| D3 | Актуальный телефон | 15/16 | Новые API, edge-to-edge, жесты |
| D4 | Планшет 7–10" | 13+ | Раскладка, размер доски |
| D5 | Huawei/Honor без GMS | 10+ | Отсутствие Google-зависимостей |
| D6 | Эмулятор x86_64 | API 26 и 36 | Быстрые smoke/CI |

Для каждого релиза — минимум **D1, D3, D4, D5**. D2/D6 — по возможности.

### 2.2. Тестовые данные

- `content/puzzles/*.json` — 180 production-задач (по 60 на уровень, 6 глав).
- `content/samples/*.json` — 4 примера формата (в APK не попадают).
- В Android-сборку паки попадают из `content/puzzles/` через Gradle-задачу
  `syncPuzzlePacks` (см. `data/build.gradle.kts`).
- Аккаунт не нужен. Для проверки серии можно менять локальную дату на
  тестовом устройстве (только в debug/эмуляторе).
- Для проверки покупок v1.1 — тестовые аккаунты RuStore, не реальные деньги.

### 2.3. Сборка

- Debug APK — для исследования.
- Release AAB/APK, подписанный release-ключом — для приёмки.
- `versionCode`/`versionName` совпадают с CHANGELOG.
- На устройстве включены RU и EN, размер шрифта 100% и 200%, TalkBack.

## 3. Приоритеты

| Приоритет | Значение | Пример |
| --- | --- | --- |
| **P0** | Блокер: нельзя решить задачу/запустить приложение | Краш на старте, нелегальная доска, таймер не идёт |
| **P1** | Критично: ломает ключевой сценарий, есть обход | Подсказка списывает токены дважды, прогресс не сохраняется |
| **P2** | Важно: заметно, но есть обход | Кривая анимация, обрезанный текст в EN |
| **P3** | Мелочь/косметика | Тень, отступ, опечатка |

P0/P1 блокируют релиз. P2 — решение релиз-менеджера. P3 — в backlog.

---

## 4. Smoke-набор (30–40 минут)

Выполняется на каждой release-сборке до полного прогона.

- [ ] Установка с нуля, запуск, главная открывается < 2 с.
- [ ] Задача дня открывается и решается.
- [ ] Уровень → глава → задача открываются.
- [ ] Верный ход принимается; неверный возвращает фигуру.
- [ ] Ответ соперника применяется; линия доходит до результата.
- [ ] Подсказка «Идея» открывается, таймер на паузе.
- [ ] Таймаут → «Продолжить» даёт +60 с и 1 попытку.
- [ ] Результат: звёзды, XP, разбор, «Следующая».
- [ ] Прогресс сохраняется после перезапуска.
- [ ] RU/EN переключаются без краша.
- [ ] Авиарежим: всё работает.
- [ ] Нет `INTERNET` и лишних разрешений в release.
- [ ] Иконка/название/версия совпадают с store-черновиком.

## 7. Проверка контента

### 7.1. Автоматически

```bash
npm ci --prefix tools
node tools/check-docs.mjs
node tools/validate-content.mjs content/samples/novice.sample.json
node tools/validate-content.mjs content/samples/professional.sample.json
node tools/validate-content.mjs content/samples/grandmaster.sample.json
```

Для production-паков:

```bash
for f in content/puzzles/*.json; do node tools/validate-content.mjs "$f"; done
```

### 7.2. Вручную

Для каждой задачи из выборки:

- [ ] FEN соответствует позиции на доске.
- [ ] Сторона хода и задание совпадают.
- [ ] Линия проигрывается без нелегальных ходов.
- [ ] Для MATE последний ход — мат.
- [ ] Нет очевидного альтернативного выигрыша (WIN/DRAW).
- [ ] Подсказка tier 1 не называет ход.
- [ ] RU/EN тексты осмысленны, без машинного перевода.
- [ ] Время укладывается в диапазон и формулу.
- [ ] Источник и лицензия указаны.
- [ ] Второй человек решил задачу без подсказок.

## 10. Что делать с найденным

1. Завести issue с шаблоном выше.
2. Добавить `KI-XXX`, если ограничение остаётся в релизе.
3. P0/P1 — исправить и повторить smoke.
4. P2/P3 — занести в backlog; не блокировать релиз без решения.
5. После релиза — проверить отзывы/краши и обновить `KNOWN_ISSUES.md`.
