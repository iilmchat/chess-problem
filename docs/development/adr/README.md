так. Они не заменяют [ARCHITECTURE](../ARCHITECTURE.md): архитектура описывает

## 2. Когда нужен ADR

ADR обязателен, если решение:

- меняет границы модулей или направление зависимостей;
- добавляет библиотеку, сеть, SDK, разрешение или хранение данных;
- меняет формат контента или контент-пайплайн;
- влияет на монетизацию, приватность, лицензии или доступность;
- выбирает между двумя и более долгосрочными вариантами;
- отменяет предыдущее ADR.

Не нужен ADR для локального рефакторинга, переименования или багфикса без
изменения контракта.

## 3. Формат

Каждый ADR содержит:

```text
# ADR-XXXX — Краткое решение

- **Статус:** Proposed | Accepted | Deprecated | Superseded by ADR-YYYY
- **Дата:** YYYY-MM-DD
- **Контекст:** что вынудило принять решение
- **Решение:** что именно выбрано
- **Последствия:** плюсы, минусы, ограничения, что придётся сделать
- **Альтернативы:** что рассматривали и почему отклонили
- **Ссылки:** связанные документы, issue, PR
```

Правила:

1. **Одно решение — один ADR.** Не смешивайте DI и выбор базы данных.
2. **Контекст важнее вывода.** Через год должно быть понятно, из чего
   выбирали.
3. **Последствия честные.** У любого решения есть цена; запишите её.
4. **Статус меняется, текст — нет.** Принятое ADR не переписывают задним
   числом. Новое решение оформляется как `Superseded by`.
5. **Ссылки относительные**, как во всей документации.
6. **Язык — русский**, идентификаторы и имена файлов — английские.

## 5. Нумерация

- Номер — четыре цифры, сквозной, не переиспользуется.
- Файл — `NNNN-kebab-case.md`.
- Следующий номер — 0009.
- ADR, отменяющее предыдущее, получает новый номер и ссылку
  `Superseded by ADR-YYYY` в старом.

---

## 6. Связь с кодом

- В PR, который реализует решение, укажите `ADR-XXXX`.
- В коде — комментарий у ключевого места: `// ADR-0003: chesslib — единственный источник правил`.
- Изменение, противоречащее Accepted ADR, требует нового ADR до мержа.
