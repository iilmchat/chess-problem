# ADR-0009 — Версионирование контента и защита прогресса в Room

- **Связано:** [ARCHITECTURE](../ARCHITECTURE.md) ·

## Контекст

В v0.2.0 демо-задачи использовали ID `nov-001`, `pro-001`, `grm-001`; в v0.2.1
те же ID получили другие позиции. Локальный прогресс тестеров стал показывать
звёзды за задачи, которые они не решали (KI-018). Публичного релиза v0.2.0 не
было, но проблема сохраняется при любом обновлении контента: в v0.4.0 в паках
360 задач (`contentVersion 2026.10.4`), а прогресс хранится в Room по `puzzleId`
без привязки к версии пака.

Без явной стратегии обновление пака может:

- показать чужие звёзды после смены позиции под тем же ID;
- стереть весь прогресс при каждом обновлении;
- оставить неактуальные строки в денормализованном кэше глав.

Приложение офлайн-first и без аккаунта (ADR-0005), поэтому серверная
синхронизация прогресса как решение не подходит.

## Решение

1. Актуальная версия контента берётся из заголовков самих JSON-паков через
   [`AssetContentVersionProvider`](../../../data/src/main/kotlin/com/iilmchat/chessproblem/data/content/AssetContentVersionProvider.kt)
   (интерфейс `ContentVersionProvider` в `:core`). Парсер читает
   `contentVersion` каждого пака и требует, чтобы все паки были одной версии;
   значение показывается на экране «О приложении». `schemaVersion` меняется
   только при ломающих изменениях схемы (ADR-0008).
2. Room повышен до версии **2**. [`Migration_1_2`](../../../data/src/main/kotlin/com/iilmchat/chessproblem/data/local/ChessDatabase.kt)
   добавляет в `puzzle_progress` колонки `chapterId` и `contentVersion`
   (`TEXT NOT NULL DEFAULT ''`) и создаёт таблицу `chapter_progress`
   (`chapterId`, `solvedCount`, `stars`, `completedAt`).
3. [`DefaultProgressRepository`](../../../data/src/main/kotlin/com/iilmchat/chessproblem/data/repository/DefaultProgressRepository.kt)
   при первой инициализации (лено, под `Mutex`, до первого запроса) вызывает
   `dao.deleteIncompatible(currentVersion)` и удаляет строки с пустой или
   неактуальной `contentVersion` — в том числе демо-прогресс v0.2.0, у которого
   после миграции версия пуста. Все записи, сохраняемые через `save()`, получают
   текущую версию пака.
4. После очистки и при каждом `save()` денормализованный кэш `chapter_progress`
   пересчитывается целиком из `puzzle_progress` (`clear()` + `recompute()`,
   группировка `GROUP BY chapterId`) по решённым задачам текущей версии.
   Инкрементальные обновления кэша не используются: на 360 задачах полный
   пересчёт дешевле и надёжнее.
5. Production-ID неизменяемы и не переиспользуются. Совпадение прогресса и
   контента определяется парой `(puzzleId, contentVersion)`: несовместимые
   строки удаляются, а не скрываются. Сеть, аккаунт и облако не используются.

## Последствия

### Положительные

- Демо-прогресс v0.2.0 больше не проецируется на production-задачи (KI-018).
- Версия контента не хардкодится: при обновлении пака несовместимые записи
  определяются автоматически.
- Кэш глав всегда согласован с исходными записями прогресса.
- Поведение покрыто unit-тестами миграции, DAO и парсинга паков в `:data`.

### Отрицательные / ограничения

- При смене `contentVersion` прогресс предыдущей версии удаляется: решение
  сознательно жертвует звёздами, чтобы не показывать чужие результаты.
- Пустое значение `contentVersion` после миграции означает «несовместимо» —
  такие строки теряются без восстановления.
- Все паки обязаны иметь одинаковую `contentVersion`; иначе чтение падает с
  ошибкой.
- Локальный экспорт прогресса по-прежнему вне MVP (ADR-0005).

## Альтернативы

| Вариант | Почему нет |
| --- | --- |
| Колонка `progress_namespace` (`demo:<version>`) | Лишний слой: достаточно версии контента и удаления несовместимых строк |
| Скрывать осиротевшие строки, не удаляя | Кэш глав и статистика продолжают видеть устаревший прогресс |
| Стирать весь прогресс при обновлении | Теряются звёзды даже при неизменном наборе задач |
| Ключевать прогресс по FEN | Ломается при исправлении позиции/линии |
| Отдельная БД на каждый пак | Сложная агрегация статистики и миграции |
| Облачная синхронизация | Противоречит ADR-0005 и обещанию приватности |
