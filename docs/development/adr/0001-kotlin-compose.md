# ADR-0001 — Kotlin + Jetpack Compose + Material 3

- **Статус:** Accepted
- **Дата:** 28.10.2026
- **Связано:** [ARCHITECTURE](../ARCHITECTURE.md) · [UI/UX SPEC](../../design/UI_UX_SPEC.md)

## Контекст

Chess Problem — Android-приложение для RuStore: портрет, доска, таймер,
анимации фигур, bottom sheet, доступность и RU/EN. Команда небольшая; нужен
стек, который:

- нативно работает на Android 8.0+ без Google Play Services;
- даёт полный контроль над кастомной доской и анимациями;
- поддерживает современный декларативный UI и превью;
- не требует кроссплатформенного рантайма и лишнего APK-веса;
- хорошо документирован и доступен на рынке.

## Решение

Используем **Kotlin 2.2.10**, **Jetpack Compose** и **Material 3**.
Навигация — Navigation Compose с type-safe routes. Тема — собственная, на
основе `design/tokens.json`. Доска — кастомный `Canvas`, а не сторонняя
библиотека.

## Последствия

### Положительные

- Полный контроль над доской, семантикой, анимациями и производительностью.
- Единый язык для UI и логики; меньше контекстных переключений.
- Material 3 даёт готовые accessibility-паттерны, темы и компоненты.
- Compose-превью и screenshot-тесты упрощают ревью UI.
- Нет кроссплатформенного рантайма: меньше APK и сюрпризов на устройствах без
  GMS.

### Отрицательные / ограничения

- Compose требует дисциплины: recomposition, стабильные ключи, отсутствие
  аллокаций в `draw`.
- Кастомная доска — больше кода, чем готовая библиотека; нужны тесты
  семантики и жестов.
- Минимальная версия Android 8.0 (API 26) ограничивает некоторые новые API;
  проверяем на API 26 и актуальном Android.
- Kotlin/Compose версии нужно синхронизировать с AGP и KSP; версии фиксируются
  в `gradle/libs.versions.toml`.

### Что сделать

- [ ] Scaffold Compose-проекта в v0.2.0.
- [ ] Вынести тему в `:ui/theme`, токены — из `design/tokens.json`.
- [ ] Настроить screenshot-тесты (Paparazzi или Roborazzi) после scaffold.
- [ ] Проверить размер APK и cold start на устройстве 2 ГБ RAM.

## Альтернативы

| Вариант | Почему нет |
| --- | --- |
| XML Views + RecyclerView | Больше boilerplate для анимаций и состояний; хуже переиспользование |
| Flutter | Лишний рантайм и вес; доступность и системные жесты требуют обходных путей |
| React Native | Тот же вес/рантайм; слабее контроль над Canvas и производительностью |
| Kotlin Multiplatform UI | Для Android-only v1.0 избыточен; iOS — исследование, не обязательство |
| Готовая board-библиотека | Меньше контроля над доступностью, фигурами и анимациями |
