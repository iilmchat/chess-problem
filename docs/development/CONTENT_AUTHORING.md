# Content Authoring

**Статус:** 180 production-задач в v0.3.0 · **Дата:** 28.10.2026
**Связано:** [CONTENT PLAN](../design/CONTENT_PLAN.md) · [схема](../../content/schema/puzzle-pack.schema.json) ·
[валидатор](../../tools/validate-content.mjs) · [Lichess selection](../../tools/lichess-selection-v030.json)

Как добавить шахматную задачу, проверить линию, написать подсказки и разбор,
собрать пак и не сломать прогресс игроков.

---

## 1. Формат

Один JSON-файл — один уровень:

```text
content/puzzles/novice.json
content/puzzles/professional.json
content/puzzles/grandmaster.json
```

Production-паки `content/puzzles/` — единственный источник контента:
перед сборкой Gradle-задача `syncPuzzlePacks` копирует их в генерируемый
assets-каталог модуля `data` (статические демо-паки удалены в v0.2.1).

Валидатор принимает и одиночный пак, и примеры из `content/samples/`.

```json
{
  "schemaVersion": 1,
  "contentVersion": "2026.10.1",
  "level": "NOVICE",
  "puzzles": []
}
```

### 1.1. Lichess-пайплайн

Для production-контента используется `tools/import-lichess.mjs`; отбор
180 задач зафиксирован в `tools/lichess-selection-v030.json`:

```bash
# 1. Скачать lichess_db_puzzle.csv.zst с database.lichess.org и распаковать
zstd -d lichess_db_puzzle.csv.zst -o lichess_db_puzzle.csv

# 2. Отфильтровать пул (≈20 минут на 6.1M строк)
node tools/import-lichess.mjs filter \
  --input lichess_db_puzzle.csv \
  --out tools/var/lichess-pool/candidates-v3.ndjson

# 3. Собрать drafts по ID из selection
node tools/import-lichess.mjs draft --pool tools/var/lichess-pool/candidates-v3.ndjson \
  --level NOVICE --chapter mate-in-1 --ids "1j4RC,0acZr,..."

# 4. Проверить факты линии
node tools/replay.mjs "<ids>" tools/var/lichess-pool/candidates-v3.ndjson

# 5. Авторинг tools/var/import-texts.json → применить и смержить
node tools/import-lichess.mjs author --texts tools/var/import-texts.json
node tools/import-lichess.mjs merge
node tools/validate-content.mjs
```

`filter` понимает и `.csv.zst`, но Node-декодер не терпит skippable frames
внутри файла; надёжнее распаковать `zstd` CLI. `merge` идемпотентен: повторный
запуск сохраняет ID существующих задач и не считает их FEN дублями.

### 1.2. Второе ревью

Перед релизом контент проходит человеческую проверку в автономном ревьюере:

```bash
node tools/review/build-review.mjs
```

Откройте `tools/review/index.html` двойным кликом: две доски, тексты RU/EN,
линия решения, статусы и комментарии; экспорт `review-notes.json`/`.md`.
Подробно — [tools/review/README.md](../../tools/review/README.md).

## 2. Поля задачи

| Поле | Тип | Обязательно | Правило |
| --- | --- | --- | --- |
| `id` | string | да | `nov-001`, `pro-001`, `grm-001`; уникален навсегда |
| `chapter` | string | да | ID главы из CONTENT PLAN |
| `fen` | string | да | Позиция **до** `setupMove`; легальная |
| `setupMove` | string \| null | да | UCI-ход соперника; `null`, если позиция уже готова |
| `solution` | string[] | да | UCI; нечётная длина; начинается с хода пользователя |
| `task.type` | enum | да | `MATE`, `WIN`, `DRAW` |
| `task.plies` | int | да | Число ходов пользователя (не полуходов) |
| `rating` | int | да | 600–2600; соответствует уровню |
| `themes` | string[] | да | 1–5 тегов Lichess/наших |
| `timeLimitSec` | int | да | 60–420; формула из DESIGN §6.1 |
| `title.ru/en` | string | да | Короткий заголовок |
| `prompt.ru/en` | string | да | Задание одной фразой |
| `hints[3]` | object[] | да | 3 уровня, оба языка |
| `explanation.ru/en` | string | да | 2–4 предложения |
| `source` | object | да | `lichess` + ID/URL + `CC0-1.0` или `original` |

### 2.1. `setupMove` — важно

В базе Lichess `FEN` — позиция **до** хода соперника, а первый ход в `Moves` —
это подводка. Пример:

```text
FEN: 6k1/5ppp/8/8/8/8/5PPP/4R1K1 w - - 0 1
Moves: e1e8
```

Здесь `setupMove = null`, `solution = ["e1e8"]`.

Если Lichess даёт:

```text
FEN: r1bqkbnr/pppp1ppp/2n5/4p3/2B1P3/5N2/PPPP1PPP/RNBQK2R w KQkq - 4 4
Moves: d8h4 f3h4
```

то `setupMove = "d8h4"` (ход соперника), а `solution = ["f3h4"]` — уже ход
пользователя. Приложение применяет подводку и показывает позицию после неё.

**Проверка:** после применения `setupMove` сторона хода должна быть стороной
пользователя. Валидатор это проверяет.

### 2.2. `solution`

- UCI, не SAN: `e2e4`, `a7a8q`, `e1g1` (рокировка).
- Начинается с хода пользователя.
- Далее чередование: соперник, пользователь, соперник…
- Длина нечётная: 1, 3, 5…
- Последний ход — пользователя.
- Для `MATE` последний ход должен ставить мат.
- Для `WIN`/`DRAW` последний ход завершает цель (мат не обязателен).

Пример мата в 2:

```json
{
  "solution": ["b1d1", "c8c7", "b2b7"],
  "task": { "type": "MATE", "plies": 2 }
}
```

### 2.3. `task`

| Тип | `plies` | Пример |
| --- | --- | --- |
| `MATE` | 1 | «Мат в один ход» |
| `MATE` | 2 | «Мат в два хода» |
| `MATE` | 3 | «Мат в три хода» |
| `WIN` | 1–6 | «Выиграйте ферзя», «Найдите лучший ход» |
| `DRAW` | 2–6 | «Сделайте ничью» |

`plies` — число ходов **пользователя**, не общее число полуходов. Для
`["b1d1", "c8c7", "b2b7"]` это 2.

### 2.4. `timeLimitSec`

```text
timeLimitSec = clamp(roundTo5(30 + 0.09 × rating + 12 × plies), 60, 420)
```

Примеры:

| rating | plies | Время |
| --- | --- | --- |
| 800 | 1 | 115 |
| 1450 | 2 | 185 |
| 2100 | 2 | 245 |
| 2300 | 5 | 310 |

Валидатор предупреждает, если значение отличается от формулы больше чем на
20 секунд.

### 2.5. Подсказки

Ровно три:

```json
"hints": [
  {
    "tier": 1,
    "ru": "Посмотрите на последнюю горизонталь: у короля нет свободного поля.",
    "en": "Look at the back rank: the king has no escape squares."
  },
  {
    "tier": 2,
    "ru": "Ладья — единственная фигура, которая может атаковать по восьмой горизонтали.",
    "en": "The rook is the only piece that can attack along the eighth rank."
  },
  {
    "tier": 3,
    "ru": "Сыграйте ладьёй на e8.",
    "en": "Play the rook to e8."
  }
]
```

Правила:

- **Tier 1 — идея.** Тема, направление, но не конкретный ход. Не называть поле
  и фигуру, если это уже ответ.
- **Tier 2 — фигура.** Можно назвать фигуру и причину, но не поле.
- **Tier 3 — ход.** Конкретный первый ход; для длинной линии — только первый
  ход, не вся линия.
- Оба языка обязательны.
- В `prompt` называйте конкретную цель: «Выиграйте ладью / слона / коня /
  ферзя», «Проведите пешку в ферзи». Не используйте общее «Выиграйте материал».
- Без спойлеров в `prompt` и `title`.

### 2.6. Объяснение

2–4 предложения:

1. Что происходит в позиции.
2. Почему первый ход работает.
3. Что получает игрок (мат, ферзь, ничья).
4. Опционально — типичная ошибка.

Плохо:

> «Правильный ход — Re8. Ладья ставит мат.»

Хорошо:

> «Король на g8 заперт пешками f7, g7 и h7. Ладья с e1 идёт на e8 и
> контролирует всю восьмую горизонталь: поля f8 и h8 тоже под ударом, поэтому
> у короля нет ни одного хода. Это типичный мат по последней горизонтали.»

### 2.7. Источник

```json
"source": {
  "provider": "lichess",
  "id": "abc123",
  "url": "https://lichess.org/training/abc123",
  "license": "CC0-1.0"
}
```

Для авторской:

```json
"source": {
  "provider": "original",
  "id": "chess-problem-original-001",
  "license": "proprietary"
}
```

Lichess ID и URL обязательны для трассировки. Имена игроков не сохраняем.

## 3. Пайплайн Lichess

### 3.1. Скачивание

База: `https://database.lichess.org/#puzzles` (CC0 1.0). Формат CSV:

```text
PuzzleId,FEN,Moves,Rating,RatingDeviation,Popularity,NbPlays,Themes,GameUrl,OpeningTags
```

### 3.2. Фильтры

- `Rating` в диапазоне уровня.
- `Popularity >= 80`.
- `NbPlays >= 1000`.
- `RatingDeviation <= 100`.
- `Themes` содержит нужную тему.
- Стандартные шахматы (без вариантов).
- Не более 1 задачи на FEN.
- Не брать задачи с рейтингом ниже 600 или выше 2400 для v1.0.

### 3.3. Импорт

1. Разобрать FEN.
2. Применить первый ход `Moves` как `setupMove`.
3. Сохранить оставшиеся ходы как `solution`.
4. Проверить, что после setup ход пользователя.
5. Сгенерировать SAN для объяснения.
6. Определить `task`:
   - если последний ход — мат, `MATE`;
   - если линия ведёт к пату/ничьей, `DRAW`;
   - иначе `WIN`.
7. Рассчитать `timeLimitSec`.

### 3.4. Машинная проверка

- FEN легален.
- `setupMove` легален.
- `solution` легальна.
- Сторона хода после setup — пользователь.
- `task.plies` совпадает.
- Для MATE — мат в конце.
- Нет дублей FEN.
- Все локализованные поля не пустые.
- Время в диапазоне.
- Тексты сверены с линией: `node tools/precheck.mjs` — число мата в промпте
  против `task.plies`, сторона хода, обещанная в WIN цель берётся в линии,
  спойлеры/SAN/поля в промпте, tier2/tier3, длина и RU/EN-синхрон разборов.

### 3.5. Ручное ревью

- Есть ли очевидный альтернативный выигрыш?
- Не слишком ли тривиально/скучно?
- Понятна ли идея за 10 секунд?
- Нет ли политики/реальных имён/спорной позиции?
- Подсказки не раскрывают ответ?
- Объяснение объясняет, а не пересказывает?

### 3.6. Локализация

- RU — редактор, знакомый с шахматами.
- EN — носитель/редактор; не машинный перевод.
- Глоссарий — в [DESIGN §13](../design/DESIGN_V01_MVP.md#13-локализация-ruen).
- SAN не переводим; названия фигур — да.

## 4. Как добавить задачу вручную

1. Создайте FEN и линию в редакторе (Lichess Board Editor / Chess.com).
2. Проверьте легальность и мат в python-chess/chess.js локально.
3. Добавьте объект в `content/puzzles/<level>.json`.
4. Заполните `setupMove`, `solution`, `task`, `rating`, `themes`.
5. Рассчитайте `timeLimitSec`.
6. Напишите `title`, `prompt`, 3 подсказки, объяснение на RU и EN.
7. Укажите `source`.
8. Запустите валидатор:

```bash
node tools/validate-content.mjs content/puzzles/novice.json
```

9. Проверьте задачу на устройстве (доска, ориентация, анимация, звук).
10. Попросите второго человека решить её без подсказок.

---

## 5. Стиль текста

- Обращение — «вы», без панибратства.
- Короткие предложения, активный залог.
- Не «очевидно», «просто», «каждый знает» — это обесценивает.
- Не спойлерить в заголовке.
- Шахматные термины — по глоссарию.
- EN — без «mate in 2 moves»; правильно `Mate in two`.
- Не использовать имена реальных игроков и названия турниров.

## 6. Частые ошибки

| Ошибка | Как ловим |
| --- | --- |
| `FEN` уже после подводки, а `setupMove` не `null` | Валидатор: после setup ход не тот |
| `solution` начинается с хода соперника | Валидатор: первый ход не пользователя |
| `plies` = длина `solution` | Валидатор: несовпадение |
| Мат в 1, а `plies = 2` | Валидатор: мат не в конце |
| Превращение без фигуры (`a7a8`) | chess.js: `promotion piece required` |
| Дубли FEN | Валидатор: duplicate FEN |
| Пустой EN | Валидатор: missing localization |
| Время 30 с для мата в 3 | Предупреждение/ошибка диапазона |
| Подсказка «Идея» называет ход | Ручное ревью |

---

## 7. Версионирование и прогресс

- ID задачи неизменяем. Не переиспользуйте ID удалённой задачи.
- При исправлении линии ID сохраняется, `contentVersion` растёт.
- Если задача стала нелегальной/спорной — удалите её и добавьте новую с новым
  ID; прогресс старой останется «осиротевшим», но не сломает приложение.
- `contentVersion` — `YYYY.MM.N`; показывается в «О приложении».
- При обновлении пака прогресс сопоставляется по ID.

## 8. Чек-лист автора

- [ ] FEN легален, сторона хода верная.
- [ ] `setupMove` (если есть) легален и отделён от `solution`.
- [ ] `solution` — UCI, нечётная длина, начинается с пользователя.
- [ ] `task.plies` = число ходов пользователя.
- [ ] Для MATE последний ход — мат.
- [ ] Нет очевидного альтернативного выигрыша (WIN/DRAW).
- [ ] Нет дубля FEN.
- [ ] `timeLimitSec` по формуле.
- [ ] 3 подсказки, tier 1 не спойлерит.
- [ ] Объяснение 2–4 предложения, RU и EN.
- [ ] Источник и лицензия указаны.
- [ ] Валидатор зелёный.
- [ ] Второй человек решил задачу.
- [ ] Проверено на устройстве.
