# Выпуск версии

**Статус:** первая редакция · **Дата:** 28.10.2026
**Связано:** [RUSTORE](RUSTORE.md) · [CHANGELOG](../CHANGELOG.md) · [QA](../qa/MANUAL_TESTING_GUIDE.md)

Пошаговый чек-лист выпуска Android-версии в RuStore. Для каждого релиза
копируйте чек-лист в issue/PR и отмечайте пункты.

---

## 1. Версионирование

- `versionName` — SemVer: `MAJOR.MINOR.PATCH` (`0.2.0`, `1.0.0`).
- `versionCode` — целое, монотонно растёт:
  `major × 10000 + minor × 100 + patch`.
  - `0.2.0` → `200`
  - `1.0.0` → `10000`
  - `1.1.0` → `10100`
- `versionCode` никогда не уменьшается: RuStore отклонит сборку.
- Тег в git: `vX.Y.Z`, аннотированный, с ссылкой на CHANGELOG.

### 1.1. Ключ подписи

1. Создайте release-keystore **вне репозитория** и сохраните его в надёжном
   месте (потеря ключа = невозможность обновлять приложение).
2. Скопируйте `keystore.properties.example` в `keystore.properties` в корне
   проекта и заполните `storeFile`, `storePassword`, `keyAlias`,
   `keyPassword`.
3. `keystore.properties` и `*.jks` уже в `.gitignore`; не коммитьте их.
4. Если файла нет, `bundleRelease` соберёт **unsigned** AAB — это удобно для
   локальной проверки, но не для публикации.

---

## 2. Заморозка

1. Создать ветку `release/vX.Y.Z` от `main`.
2. Заморозить контент: `contentVersion` зафиксирован.
3. Обновить `CHANGELOG.md`: раздел `[X.Y.Z]` с датой.
4. Обновить `versionName`/`versionCode` в `app/build.gradle.kts`.
5. Проверить, что `KNOWN_ISSUES.md` актуален.
6. Согласовать store-тексты и скриншоты.

---

## 3. Проверки

```bash
# 1. Чистая сборка
./gradlew clean build

# 2. Unit-тесты
./gradlew :app:testDebugUnitTest

# 3. Lint + detekt
./gradlew :app:lintDebug detekt

# 4. Контент
npm ci --prefix tools
for f in content/puzzles/*.json; do node tools/validate-content.mjs "$f"; done
node tools/check-docs.mjs

# 5. Release AAB
./gradlew :app:bundleRelease

# 6. Подпись
$ANDROID_HOME/build-tools/36.0.0/apksigner verify --verbose --print-certs \
  app/build/outputs/apk/release/*.apk
```

- [ ] Все тесты зелёные.
- [ ] Lint/detekt без ошибок (warnings — разобраны).
- [ ] Контент-валидатор зелёный на всех паках.
- [ ] Ссылки в документации зелёные.
- [ ] Release AAB собран.
- [ ] Подпись тем же сертификатом.
- [ ] Нет `debuggable`, `INTERNET` (для v1.0.0), лишних разрешений.
- [ ] R8 mapping сохранён.

---

## 4. QA на устройстве

- [ ] Пройти [MANUAL_TESTING_GUIDE](../qa/MANUAL_TESTING_GUIDE.md) smoke-набор.
- [ ] Проверить на Android 8.0 (или эмуляторе) и актуальном Android.
- [ ] Проверить 2 ГБ RAM / 720p.
- [ ] Проверить планшет 7–10".
- [ ] Проверить RU и EN, шрифт 200%, TalkBack.
- [ ] Проверить таймер, фон/возврат, process death.
- [ ] Проверить офлайн (авиарежим).
- [ ] Проверить все 5 скриншотов на реальном устройстве.

---

## 5. Store-артефакты

- [ ] Иконка 512×512 PNG, без прозрачности.
- [ ] ≥3 скриншота телефона, ≥3 планшета.
- [ ] Название ≤30, краткое ≤80, подробное ≤4000.
- [ ] Категория, возраст 6+, маркировки, контакты.
- [ ] Политика конфиденциальности доступна по URL.
- [ ] Декларация данных заполнена.
- [ ] «Что нового» — 3–6 пунктов, без технического шума.
- [ ] Лицензии Lichess/шрифтов/библиотек в приложении.

---

## 6. Публикация

1. RuStore Консоль → «Приложения» → выбрать приложение → «Загрузить версию».
2. Загрузить AAB/APK, дождаться обработки (файлы хранятся 14 дней).
3. Заполнить «Что нового?».
4. Проверить карточку и скриншоты.
5. Сохранить черновик → «Отправить на модерацию».
6. После одобрения — публикация (если доступен staged rollout, начать с 10–20%).
7. Мониторить краши, отзывы, установки 24–72 часа.

---

## 7. После релиза

- [ ] Создать тег `vX.Y.Z` и push.
- [ ] Обновить `CHANGELOG.md` (дата, ссылка на релиз).
- [ ] Проверить, что бейдж версии в README обновлён.
- [ ] Собрать метрики: установки, D1, отзывы, краши.
- [ ] Завести issues на найденные проблемы.
- [ ] Решить, нужен ли hotfix.

---

## 8. Hotfix

1. Ветка `hotfix/vX.Y.Z+1` от тега релиза.
2. Минимальное исправление + тест.
3. `versionCode` +1 (или patch +1).
4. CHANGELOG: `### Fixed`.
5. Сборка, QA smoke, загрузка в RuStore.
6. Не менять ключ и package.

---

## 9. Откат

RuStore не позволяет откатить установленную версию у пользователей. Если релиз
сломан:

1. Остановить rollout (если доступно).
2. Выпустить hotfix как можно быстрее.
3. Обновить карточку/описание, если проблема в тексте.
4. Уведомить пользователей в отзывах/соцсетях.
5. Зафиксировать инцидент в `KNOWN_ISSUES.md`.

---

## 10. Definition of Done

Релиз считается завершённым, когда:

- версия опубликована в RuStore;
- тег и CHANGELOG обновлены;
- smoke-набор пройден;
- нет P0/P1 багов;
- политика и лицензии доступны;
- метрики собираются (или осознанно отключены);
- команда знает, что делать с отзывами и крашами.
