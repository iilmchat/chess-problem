# Правила проекта

Обязательные правила для команды: код, контент, документация, git, PR,
лицензии и приватность. Нарушение — повод не мержить PR.

---

## 1. Код

### 1.1. Стиль

- Kotlin — официальный стиль; форматирование — `detekt-formatting` (ktlint),
  подключается в v0.2.x (KI-016).
- Имена: `camelCase` — функции/переменные, `PascalCase` — типы,
  `SCREAMING_SNAKE_CASE` — константы в `companion object`.
- Комментарии — по-русски, объясняют «почему», а не «что».
- Никаких `!!`, `lateinit` без обоснования, `TODO` без ссылки на issue.
- Максимальная длина строки — 120 символов (см. `.editorconfig`).

### 1.2. Слои

- `:core` — чистая логика. **Никаких** импортов `android.*`, `androidx.*`,
  `:ui`, `:data`.
- `:ui` — Compose и ViewModel. **Никаких** импортов `:data`; только интерфейсы
  `:core`.
- `:data` — Room/DataStore/JSON. Не импортирует `:ui`.
- `:app` — единственное место сборки DI-графа и platform-адаптеров.
- Шахматные правила — только через `ChessRules`; composables не вызывают
  chesslib напрямую.

### 1.3. Состояние

- Однонаправленный поток: событие → ViewModel/`PuzzleSession` → неизменяемое
  состояние → UI.
- Никакой мутации состояния из composable.
- `StateFlow` + `collectAsStateWithLifecycle()`.
- Таймер — в `core`, не в composable; UI только тикает.

### 1.4. Тесты

- Изменение `core` требует unit-теста.
- Тест проверяет поведение, а не реализацию.
- Имена тестов — на русском в backticks, описывают ожидание:
  `` `неверный ход возвращает позицию` ``.
- Perft-тесты обязательны при изменении шахматного ядра/обновлении chesslib.
- Контент — валидатор в CI; ручное ревью — вторым человеком.

### 1.5. Производительность

- 60 FPS на среднем устройстве; просадка ниже 45 — баг.
- Не создавать объекты в `draw`/горячем цикле; кэшировать фигуры, кисти, пути.
- Не блокировать main thread; JSON-парсинг — на `Dispatchers.IO` при старте.
- Не добавлять сетевые SDK без ADR и обновления политики.

## 2. Контент

- Формат — JSON по [схеме](../../content/schema/puzzle-pack.schema.json).
- ID задачи неизменяем; удалённые ID не переиспользуются.
- `solution` — UCI, нечётная длина, начинается с хода пользователя.
- `task.plies` — число ходов пользователя.
- Для MATE последний ход — мат.
- Нет очевидного альтернативного выигрыша для WIN/DRAW.
- 3 подсказки, tier 1 не спойлерит.
- RU и EN обязательны; машинный перевод без редактуры — нет.
- Источник и лицензия указаны; Lichess — CC0 1.0.
- Любое изменение контента — валидатор + второе ревью.

## 3. Документация

### 3.1. Структура

```text
docs/
├── README.md                    ← хаб
├── CHANGELOG.md                 ← Keep a Changelog
├── KNOWN_ISSUES.md              ← KI-XXX
├── design/                      ← DESIGN, UI/UX, CONTENT PLAN
├── development/                 ← ARCHITECTURE, GETTING_STARTED, RULES,
│                                   RELEASES, RUSTORE, CONTENT_AUTHORING
│   └── adr/                     ← архитектурные решения
├── qa/                          ← ручное тестирование
├── user_guide/                  ← руководство игрока
└── legal/                       ← политика, лицензии
```

### 3.2. Правила

1. Изменили поведение — обновили DESIGN/UI-спецификацию и CHANGELOG в том же PR.
2. Приняли архитектурное решение — записали ADR.
3. Добавили модуль/точку расширения — обновили ARCHITECTURE.
4. Новый документ — добавили в `docs/README.md` и в README.
5. Ссылки — относительные; `node tools/check-docs.mjs` должен быть зелёным.
6. Документация и тексты — на русском; идентификаторы/коммиты — на английском.

### 3.3. Известные проблемы

- `KI-XXX` присваивается один раз.
- Закрытая проблема переносится в «Решённые» со ссылкой на версию.
- P0/P1 — блокируют релиз.

## 4. Git

### 4.1. Ветки

- `main` — защищённая, только проверенный код.
- `feature/<short>` — функциональность.
- `fix/<short>` — исправление.
- `content/<short>` — задачи и локализация.
- `chore/<short>` — инфраструктура/документация.
- `release/vX.Y.Z` — заморозка релиза.

### 4.2. Коммиты

Conventional Commits:

```text
feat(core): добавлена сессия задачи с тремя попытками
fix(ui): таймер не останавливается при открытии подсказки
content(novice): добавлены 10 задач главы «Вилка»
docs(rustore): уточнены требования к скриншотам
chore(deps): обновлён chesslib до 1.3.7
```

Тело коммита — если изменение неочевидно: почему так, а не иначе.

### 4.3. Не коммитить

- `local.properties`, `keystore.properties`, `*.jks`, `*.keystore`.
- `build/`, `.gradle/`, `.kotlin/`, `tools/node_modules/`.
- Собранные APK/AAB.
- Секреты, токены, персональные данные.

---

## 5. Pull request

1. PR описывает **что** и **зачем**; шаблон — `.github/pull_request_template.md`.
2. CI зелёный: docs, content, Android unit-тесты, debug APK и lint.
3. Минимум один аппрув.
4. Изменённые документы перечислены.
5. Крупная архитектура — сначала ADR, потом код.
6. Контент — второе ревью и валидатор.
7. Скриншоты/видео для UI-изменений.

---

## 6. Релизы

- SemVer; `versionCode` монотонно растёт.
- Каждая версия — запись в CHANGELOG и тег `vX.Y.Z`.
- Процедура — [RELEASES.md](RELEASES.md).
- Ключ подписи — вне репозитория, backup в менеджере паролей.
- Потеря ключа = невозможность обновления.

---

## 7. Лицензии и ассеты

- Сторонние библиотеки — только Apache/MIT/BSD/OFL/CC0 или совместимые.
- Каждый ассет — с лицензией рядом или в `THIRD_PARTY_LICENSES.md`.
- Шахматные задачи Lichess — CC0 1.0; атрибуция в приложении.
- Шрифты — OFL/Apache, с кириллицей; лицензии в `assets/fonts`.
- Фигуры — собственные; не копировать Cburnett/Chess.com без лицензии.
- Иконка/скриншоты — без чужих логотипов и реальных лиц.
- `python-chess` (GPL) **не** используется в репозитории; валидатор — chess.js
  (BSD-2-Clause). Не добавлять GPL-инструменты в продакшн-пайплайн без
  юридической проверки.

---

## 8. Приватность

- v1.0.0: нет сети, аккаунта, аналитики, рекламы, IAP.
- Любой новый SDK/разрешение — сначала политика, декларация RuStore, ADR.
- `allowBackup=false`; прогресс не уходит в облако.
- Не логировать PII; в debug — только ID задач.
- Политика конфиденциальности доступна по URL до релиза.

---

## 9. Доступность

- Новый экран — проверка контраста, TalkBack, 200% текста, 48 dp.
- Не полагаться только на цвет.
- `reduce motion` уважается.
- Доска — семантика клеток и альтернативный список ходов (v0.4.0).
- Accessibility-баг — P1, если блокирует решение задачи.

---

## 10. Definition of Done для фичи

- [ ] Поведение описано в DESIGN/UI-спецификации.
- [ ] Код в правильном слое, без циклических зависимостей.
- [ ] Unit-тесты (для `core`) и UI-тест (для экрана).
- [ ] Контент-валидатор (если контент).
- [ ] RU/EN строки.
- [ ] Доступность проверена.
- [ ] CHANGELOG обновлён.
- [ ] CI зелёный.
- [ ] Ревью пройдено.
